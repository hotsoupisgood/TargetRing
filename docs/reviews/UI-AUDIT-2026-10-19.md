# UI audit — the published tool and the flowchart, 2026-10-19

Puck, with a phone screenshot of an empty white rounded box and an empty dark
box above "The 12 ring scales": *"this looks bad. do a full audit of the ui
please. revise until you are happy with your work"*.

## How it was done

`scripts/ui_audit.py` drives Chromium over the tree `docs/` actually serves,
under a `/TargetRing/` path prefix (the way GitHub Pages serves it), at **390 px**
and **1280 px**. It opens every tab, forces every `<details>` open, and opens a
drawer, because a defect behind a click is still a defect. On each view it
reports:

| | what it measures |
|---|---|
| **empty-box** | a visible, bordered or filled container with no text, no media and no children |
| **contrast** | WCAG ratio from the **composited** colours actually painted, with the 4.5:1 / 3:1 split by font size and weight |
| **overflow** | an element past the viewport, or wider than its own box, **discounting** a scrolling ancestor and absolutely positioned descendants |
| **clipped** | text taller than a box with `overflow: hidden` |
| **dead-link / maybe-dead-button** | an `<a>` with no `href`, a `<button>` nothing is bound to |
| **broken-image** | `naturalWidth === 0` |
| **tiny-text** | under 11.5 px, Puck's own floor rather than a WCAG rule |
| console errors, failed requests | collected per view |

Six passes were run. Measuring the composited colour rather than the declared
one is what found the contrast failures: every one of them was declared against
a token that looked fine in isolation.

| pass | findings | what changed |
|---|---|---|
| 1 | 541 | the first look |
| 2 | 147 | the eight fixes below, plus three probe corrections |
| 3 | 34 | cell ink, ledger tables |
| 4 | 8 | remaining prose tables |
| 5 | 8 | screenshots; no new findings |
| 6 | 8 | prose trimmed; no new findings |

Passes 5 and 6 found nothing new. The eight that remain are the same two table
cells, reported once per view and per width, and are **accepted with a reason**
— see the last section.

## What the two empty boxes were

`#cell-states` (the four cell states) and `#wedge-note` (the sentence that
explains the gap at 12 o'clock). Both are filled by `renderDecode`, which is
called only from the live analyse path — and `/api/run/{id}/scales`, the route
that feeds it, answered **404 for every run not in this process's memory**,
which is every run a demo serves. So the published page drew two bordered boxes
with nothing in them, exactly as the screenshot shows.

Fixed in three places, because it had three causes:

1. `/api/run/{id}/scales` now answers from `values.csv` through `table.load`,
   the same pivot the Table tab reads (`app.py`). It refuses with **409 and a
   sentence** for a run drawn against ring specs this build no longer declares —
   found the same day: a run whose `rodent` ring holds a raw count of 181 where
   the spec declares [0, 1]. A scale drawn from another build's ranges would
   decode that run's colours as numbers it does not hold, so no scale is drawn.
2. The static export writes `scales.json` and the shim maps the route onto it.
   Without that the fix above was invisible on the published site.
3. `hideEmptyDecodeBoxes` + `:empty` CSS: a box with no text is not drawn at
   all, so this cannot recur silently in a surface nobody anticipated.

### Probe corrections (false positives the first pass produced)

Recorded because a noisy audit is a worse instrument than a strict one, and
222 of pass 1's 541 findings were one dropdown counted many times:

* a wide table inside a **scrolling ancestor** is not an overflow;
* an ancestor whose only over-wide descendant is **absolutely positioned** is
  not overflowing — one 350 px dropdown made `main`, `#result` and
  `#pane-figure` all report 553 px;
* a **form control with a value** is not an empty box (`innerText` cannot see
  `.value`, so `#disease` holding "Crohn's disease" was reported as empty);
* a full-viewport **overlay** (`#scrim`) is empty by design;
* SVG `<text>` has no meaningful `clientWidth`.

## Accepted, with the measurement

**Two value cells, 4.31:1 and 4.28:1 against AA's 4.5:1**, at 12.5 px, on fills
`rgb(145,119,41)` and `rgb(96,128,129)`.

The fill may not move: it is the colour `values.csv` recorded, which is the
colour the arc was painted, and this table does not choose a palette. For those
two ramp mid-steps **neither** ink reaches 4.5:1 — white is 4.31:1 / 4.28:1 and
black is 3.95:1 / 4.02:1 — so `inkOn` returning the better of the two is as far
as an ink choice can get. A **halo in the opposite ink** closes the gap in
practice, raising local contrast at every glyph edge, which is where legibility
is decided; WCAG's formula models a flat background and cannot see it, so
`scripts/ui_audit.py` still reports these two. The number is also in the cell's
`title`, in `values.csv` and on the figure.

**Closing it properly is Puck's call**, because it means moving two mid-steps of
the figure's own ramps (`docs/design/palette.md`), which changes the colours of
every figure this build has drawn.

# Button flow and history — 2026-10-19

Puck: *"check the button flow and back buttons. make sure the header is
maintained on the flow page."*

Every control on both published pages was exercised with Playwright against the
tree served under a `/TargetRing/` prefix — the path shape GitHub Pages uses,
which is the shape the two bugs below only appear in. **71 checks, 0 failing**
after the fixes. The input path (paste, the two example loaders, *Draw the
figure*) does not exist on the read-only export, so it was exercised against
the local app instead; which surface each check ran on is stated below.

## What was broken

### 1. Every download on the published site was a 404

`app.js` fills the Figure / Legend / Data menus with `el.href = "/api/run/…"`
on anchors that are **already in the document**. `static_demo_shim.js` rebased
three kinds of URL — `fetch()`, `innerHTML` writes and inserted nodes — and a
property assignment is none of them. So on a site served under `/TargetRing/`
all ten items pointed at the host's root.

This was invisible locally, where the demo is served at `/` and the un-rebased
path happens to be right. It was wrong on every published build.

**Fixed** by patching the `href`/`src` setters on `HTMLAnchorElement` and
`HTMLImageElement` in the shim, the same shape as the existing `innerHTML`
patch and for the same reason: an attribute observer fires after the anchor is
already wrong, and a click in that window downloads the 404. Non-rewritable
URLs — external, `blob:`, already relative — pass through untouched.

### 2. Two menu items pointed at files the export never wrote

`values.json` carries an `artefacts` list read off the run's own directory, and
`diskRunDownloads` correctly removes any item missing from it. The list was
right about the server and wrong about the export: `figure-slide.svg` and
`figure-slide.png` are deliberately not exported (+1.4 MB a run), so *Slide SVG
(16:9)* and *Slide PNG (16:9)* were live items that 404ed.

**Fixed** in `export_static_demo.py` (`only_exported_artefacts`), not in
`view.py` — the server's answer is correct about the server, and the export is
what knows which files it chose to leave behind. With `--keep-slides` the list
is untouched.

### 3. The tool had no history at all

Six tabs and a full-height drawer were states of one URL, so Back did the only
thing it could and left the site — on the published build, onto the
`docs/index.html` redirect stub, which reloads the tool and drops the run.

**Fixed** with a hash router in `app.js` (`#<tab>` / `#<tab>/<gene>`). The rules
are in the comment above `goTab`; the load-bearing ones are that painters never
push, that re-selecting the current view pushes nothing, and that the drawer's
× is `history.back()` — which is also what restores the reader's scroll
position, since the browser already saved it.

### 4. The flow page scrolled itself off the top on load

`select()` called `scrollIntoView` unconditionally, including on the opening
paint. At ≤880 px the detail pane stacks below the chart, so the page opened
scrolled 686 px down with its own masthead off screen. **Fixed**: scrolling is
a response to a click, never to a render, and only when the pane is out of
view.

### 5. The flow page had no box addresses, and its links went through the stub

No hash, so Back walked off the site mid-read and no box could be linked to.
**Fixed** with `#box-<id>`, `popstate`/`hashchange`, arrow-key navigation
between boxes, and `replaceState` on the opening paint so one Back returns to
the tool rather than to the page you are already on. A stale `#box-…` falls
back to the first box instead of a dead pane.

Separately, every "open the tool" link on the page was `href="../"`, which
lands on the meta-refresh stub. All four now name `../demo/` directly.
`tests/test_flow_header.py` holds that.

## The shared masthead

`docs/flow/` had its own `<h1>` and no wash. It now carries the tool's masthead
verbatim — same markup, same type, same wash — with its own lede under it. The
geometry is restated as literal values rather than by linking `app.css` (which
would restyle the chart, the panels and the detail pane); the wash *is* linked,
because `header-wash.css` names its image relative to itself and so works
unchanged from either directory.

`tests/test_flow_header.py` holds the copy to the original: seventeen
`--tr-*` token values, the `<h1>` verbatim, and the rule that the flow page
never links `app.css` and never names the png itself.

Both pages gained a nav row (**Tool** / **How it works**, current one marked).
It lives in `static/index.html` so the masthead stays assembled in one file,
and `app.css` hides it unless `<body>` carries `data-site="pages"`, which only
the exporter sets — the live app has no `../flow/` to point at, and a link to
a page that is not there is worse than no link.

Measured at 390 px and 1280 px: background colour and image, size and position,
padding, min-height, border, font stack, h1 size / line-height / tracking /
weight, the `.ver` span, the nav's display and type, the lede's size and
colour, the title's x and y, and the band's own height are **identical on both
pages at both widths**.
